# 任务：钱博士Agent 从「财经内容摘要系统」升级为「投研决策台」的架构设计

你是资深AI系统架构师 + 买方投研决策支持系统专家（不是量化交易专家）。请基于下述**现有架构**，叠加**新业务需求**，输出完整的架构设计方案。必须具体可落地，禁止泛泛而谈（"加强缓存""优化提示词"不算方案）。所有方案必须回答：怎么改、新模块怎么设计、数据结构长什么样、预期收益、工作量/成本估算。

## 一、明确定位（最高原则）

本系统**不是量化交易系统，不产生买卖信号，不自动交易**。最终投资决策人永远是用户本人（实盘炒股的个人投资者）。

系统的定位是：**投研决策台** —— 把信息摆清楚、把逻辑链连起来、把历史证据标出来，放大用户的认知和判断力，而不是替代判断。

个人投资者做量化的三重劣势（信息、执行、资金成本）意味着这条路走不通；用户的核心资产是判断力，系统只做三件事：**信息对照、重点标注、推理辅助**，外加**长期学习进化**（沉淀用户自己的认知演进）。

### 2.2 现有架构文档 v0.3 的核心原则（2026-07-21定稿）

1. RAG 从"主判断器"降级为"证据补充器"；盘前简报主观点必须来自 latest_digest 或 structured_views/query_views
2. 日期、实体、来源、观点类型先硬过滤和分桶，桶内才打分；不要继续只调相似度/新鲜度权重
3. 行情事实层与观点层分离；A股非交易时段只显示昨收/缓存价，不伪装实时涨跌
4. LLM 只做综合表达，不做检索裁判、数据验证和最终格式控制
5. 每条观点必须能回溯到 view_id/source_file/date/analyst/evidence
6. 已规划用 view_id 做 1/3/5/10/20 日收益、超额收益、最大回撤验证闭环（validate.py 雏形已存在，未成体系）

### 2.3 structured_views.jsonl 字段规范（已落地，新设计必须兼容）

每行一条观点：`view_id / source_file / source_bv / source_type / analyst / date / section / timestamp / entities(sectors/stocks/etfs/themes) / stance(bullish/bearish/neutral/risk/watch) / horizon(intraday/short/medium/long) / view_type(market/sector/stock/risk/framework/event/validation) / claim / logic / risk / evidence(原文引用20-300字) / confidence / quality_flags`

### 2.4 gpt-5.5 前次深度审计结论（2026-08-04，已采纳，路线图推进中）

系统是"财经内容摘要系统"，不是"可追溯可验证的投研证据系统"。三个最高价值优化：
1. **ViewCard + EvidenceChain 生成**：日报每个观点卡片绑定 谁/何时/原话/理由/例证/反证/风险条件/历史同类判断
2. **PredictionEvent 回测库**：prediction_events + market_outcomes + analyst_scores 三张表（SQLite起步）——"每个分析师对每个板块/标的的历史判断列举正误"的地基
3. **RAG 从 chunk 检索升级 EvidencePack 检索**（观点+原文+历史预测+市场验证）

落地路线图已有雏形：一阶段证据链基础 → 二阶段回测MVP（validate.py + structured_views.jsonl 已有雏形可加速）→ 三阶段RAG证据检索 → 四阶段管线工程化。

## 三、新业务需求（本次架构设计要新增的核心，围绕它展开全部设计）

### 需求1：信息对照层 — 多空对照卡（重点标注）

对每个重点资产/板块/标的，生成一张「多空对照卡」：多头论据清单 + 空头论据清单 + 分歧点（哪些分析师在打架，各站哪边）+ 共识点（所有人一致的方向）。

**重点标注**三样东西：①高置信判断（分析师给了强理由+高置信度）②强分歧（同一资产多空激烈对立）③新变化（最近N天观点方向翻转，或新出现的关键证据）。标注要在卡片和日报里视觉/结构上突出。

数据来源：structured_views.jsonl（按 entity 聚合 stance）→ 需要设计"观点聚类/分歧检测"模块（同 entity、同 horizon 的观点按 claim 语义聚类，找出对立与一致）。

### 需求2：推理框架层 — 资产分析卡（用户点名的核心）

每个资产/板块一张「分析卡」，明确列出它的**驱动因素清单**，以及每个因素的当前状态。这是用户原话的落地："某个固定模块要参考哪些信息才能推理趋势，比如黄金判断需要跟美元强挂钩"。

示例（黄金分析卡）：
```
驱动因素：美元指数、美债实际利率、地缘风险、央行购金、避险情绪、通胀预期
每个因素需给出：当前状态（来自行情数据/最新观点）、变化方向（向上/向下/持平）、
对黄金的影响方向（正/负/中性）、历史正误记录（该因素此前驱动判断的验证结果）
```

设计要点：
- 因素清单本身是**可编辑的知识资产**（配置文件或库表），不是写死在代码里；用户可增删因素
- 每个因素绑定数据来源：能拉行情的绑行情源（如美元指数→DXY），能看观点的绑观点检索（如地缘风险→RAG搜"地缘"）
- 因素状态自动刷新（定时拉取或按需拉取），变化方向与影响方向结合产出"该资产当前逻辑链"摘要
- 分析卡要有版本号，用户认知演进时更新（见需求3）

### 需求3：决策复盘层 — 长期学习进化的引擎

三条具体进化回路，不做模型训练，全部是数据沉淀+定期复盘：

1. **分析师正误追踪**（延续已有规划）：view_id → 1/3/5/10/20日收益回测 → 每个分析师每个板块的历史准确率 → 作为该分析师当前判断的可信度参考，在对照卡/日报中呈现
2. **用户决策日志**：用户每次拍板（"我看好黄金，因为美元见顶+央行购金"）记录一条：判断方向+理由+依据（当时引用的观点/数据快照）。过段时间回填市场结果。定期复盘：对了/错了、当时漏看了哪个因素。复盘结论沉淀进分析卡更新
3. **分析卡版本化**：复盘发现的认知修正（如"美元与黄金负相关只在降息周期强"）写入分析卡新版本，卡有版本历史，可回看认知演进

### 需求4：交互形态（设计时考虑，可给方案选项）

- 最低成本：分析卡/对照卡作为盘前简报的固定区块（Markdown 生成）
- 中期：Feishu/Studio 聊天问答（"黄金现在怎么看"→ 自动拼装 分析卡+最新观点+行情）
- 后期：独立浏览界面（资产卡+对照+复盘时间线），审美基准：简约高级（LobeChat/shadcn-admin级），用户已否定Streamlit默认风格
