# ADR-002：DSH 定位（开发者入口，非产品壳）

- 日期：2026-09-03
- 状态：接受

## 背景

8-29 DSH 调研后曾讨论"交互放 DSH 还是自研"。9-3 实测：iframe 嵌套 DSH web UI 进作品集页面被否（双壳/双导航/主题冲突，观感割裂）；且 DSH 为单机 profile 体系（~/.dsh），无账号/多租户，RC 预览期无移动版。

## 决策

1. **DSH = 开发者调试/内部验证入口**（qianboshi profile + MCP 13 工具，127.0.0.1:3080），产品页只保留页脚"开发者入口"链接。
2. **产品入口 = Portfolio 前端（/agent 研究工单台）+ 后端 API**，面向终端用户。
3. Hermes = qianboshi MCP 工具宿主与维护通道（不变）。

## 理由

- 产品化需要多用户、鉴权、品牌界面，DSH 架构不支持
- 避免产品界面依赖本地运行的第三方 web 服务
- DSH 的轨迹可视化/工具审计思想由自研工作台（P2）吸收

## 后果

- DSH 对话链路问题（工具结果回填后模型总结卡顿，dsh-mcp-client 0.1.1-rc.2 嫌疑）不阻塞产品 API
- P2 工作台实现"工具轨迹/权限/审计"时以 DSH 为参考不依赖
