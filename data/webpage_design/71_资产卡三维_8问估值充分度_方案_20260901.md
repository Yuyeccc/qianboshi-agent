## 4. #10 资料充分度（asset 卡三维，先做，其他两项依赖它）

### 4.1 yaml 新增 `data_status` 块

```yaml
data_status:                    # 值域 available/pending/insufficient/na（见语义表）
  market: available             # 行情
  views: available              # 观点
  fundamentals: available       # 财报（个股卡；ETF/商品卡：na）
  valuation: available          # 估值 PE/PB 分位（个股卡；ETF/商品卡：na）
```

| 值 | 中文 | 语义 |
|---|---|---|
| available | 已拿到 | 数据源实测可用且已取数 |
| pending | 待补 | 有明确数据源但未接入/未拉取 |
| insufficient | 不足 | 数据存在但稀疏/过期（如最新财报公告距今 >2 季度） |
| na | 不适用 | 资产类型本无此数据（ETF 无财报），**不是缺陷** |

### 4.2 质量因子卡（#10 的"质量因子卡"，通用 4 因子）

yaml 新增 `quality_factors` 块。**所有指标强制带 period（报告期）/ unit（单位）/ source（来源）**，口径写死在评估规则里：

```yaml
quality_factors:
  - factor_id: NET_DEBT
    factor_name: 净有息债务
    category: debt
    data_binding:
      type: fundamental
      symbol: "601899.SS"
      source: baostock
      metrics: ["short_loan", "long_loan", "bond_payable", "monetary_fund"]  # 短借+长借+应付债券-货币资金
    assessment_rule: 正值且环比上升 → "债务压力↑"；负值 → "净现金"
    note: 只含有息负债，不含应付账款等经营负债（gpt审P1-3修正）
  - factor_id: ASSET_EXPOSURE
    factor_name: 减值敏感资产暴露
    category: impairment
    data_binding:
      type: fundamental
      metrics: ["accounts_receivable", "inventory", "goodwill", "fixed_assets", "cip"]  # 应收+存货+商誉+固定资产+在建
    assessment_rule: 占总资产 >40% → "减值敏感"；20-40% → "关注"；<20% → "轻"
    note: 矿业含固定资产/在建（资源储量载体），不能只看应收存货（gpt审P1-4修正）
  - factor_id: CASHFLOW_QUALITY
    factor_name: 盈利质量
    category: quality
    data_binding:
      type: fundamental
      metrics: ["net_operate_cashflow", "net_profit"]
    assessment_rule: 经营CF/净利 >1 → 含金量高；0.5-1 → 正常；<0.5 → 含金量低
```

- **通用类**：净有息债务 / 减值敏感资产暴露 / 盈利质量 / 利息负担（财务费用/营业收入）4 个
- **地产特化**（存货/去化/合同负债）：写模板 `configs/asset_cards/real_estate.yaml.example`（示例卡，不激活）——当前 8 卡无地产卡，机制先备好
- **黄金特化**：财政风险溢价三因子（#19 ✅ 已落地），不重复做
- **拉不到数据 → 该因子 data_status=pending，显示"待补"，不算数、不产生方向**

现 `_base_state()` 在 `current_state=="数据缺失"` 时仍给 `confidence=0.6`；`refresh_factor` 的 manual 分支缺值时直接把 relation 当 impact_direction（"手工值缺失"却显示"对GOLD构成positive影响"）——**违反"不猜数据"红线**。修正规则：

## 6. #9 绝对估值 calc（估值水位，价格维度）

### 6.1 新模块 `scripts/valuation_calc.py`（确定性，零 LLM）

输入：A股个股代码（当前仅 ALUMINUM→601899.SS 配置；ETF/商品卡不配不渲染）

**步骤 1：取数与清洗（gpt审P1-1吸收）**
- baostock 拉近 **3 年** 日K `peTTM/pbMRQ`（~750 条，实测可行）
- 清洗规则：
  - `PE<=0`（亏损）或 `PB<=0` 或 NaN → **剔除，不进分位**（记录剔除数）
  - 按交易日去重（重复日期只留一条）
  - 记录：有效样本数 / 剔除数 / 覆盖跨度 / 最近观测日期 / PE-PB 同日交集数

**步骤 2：数据充分度闸门（gpt审P1-5/P2-1吸收）——不达标不算估值**

| 门槛 | 阈值 |
|---|---|
| PE、PB 有效样本数 | 各 ≥250 条（约 1 年交易日） |
| 覆盖跨度 | ≥2 年 |
| 最近观测时效 | 距 as_of_date ≤30 天 |
| PE/PB 交集 | 交集数 ≥250 |

任一不达标 → 估值档位 = `数据不足`（insufficient），风险分栏照常尝试，无数据栏显示"待补"。

**步骤 3：分档（确定性查表，仅当闸门全过）**
- 分位算法：`percentile` 用 `statistics.quantiles`（linear 插值，n=4 分位），当前值取最近有效交易日
- PE 分位 ≤25% 且 PB 分位 ≤25% → **一眼便宜**
- PE 或 PB 分位 >75% → **未达门槛**
- 其余 → **临界**

**步骤 4：风险分栏（估值≠安全边际，红线核心），每栏确定性计算**
- **减值敏感资产暴露**：应收+存货+商誉+固定资产+在建 / 总资产（触发警示阈值 40%）
- **净有息债务**：短借+长借+应付债券-货币资金
- **盈利质量**：经营CF / 净利润
- 全部带 period/unit/source；财报取**最新公告日 ≤ as_of_date** 的一期（baostock 返回 pubDate，天然 point-in-time；财报距今 >2 季度 → data_status 降 insufficient）

**步骤 5：底部固定提示（渲染层硬编码，不可被配置覆盖）**
> ⚠️ 估值≠安全边际：便宜可能含价值陷阱（如 0.5x PB 假低估），须结合质量因子与资料充分度综合判断，本卡不构成买卖建议。
