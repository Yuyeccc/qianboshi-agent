### 5. ⚠️ 实测发现 v1 回撤口径 bug（必须修）

实跑 `discipline_checker.py --json` 输出：**drawdown = 61.5% 超阈值 15%**，但用户实际组合是盈利的（黄金 +91.62、创新药 +37.29 已卖出回收）。

根因：`drawdown = 1 - total_cost / Σ(history buy.amount)` = 1 - 500/1300 = 61.5%。
- 基准「累计买入额」把**已平仓并回收资金**的仓位也算进投入（1300 = 黄金 800 + 电池 500），但卖出回收 1917.92 没扣
- 且 history 缺 159992 买入 989.01，基准本身就少算
- 结果：**盈利组合被误报 61.5% 巨幅回撤**。嵌入决策台后这误报会每天进盘前简报，直接污染日报 → 必须 P0 修正

**修正口径（成本口径，不引入行情依赖）**：
- 已投入总成本 = Σ closed_positions.cost + Σ holdings.buy_amount（closed_positions 是已平仓权威记录，补 history 缺失）
- 已回收 = Σ closed_positions.proceeds
- 净投入 = 已投入总成本 - 已回收
- 回撤 = (净投入 - 当前持仓成本) / 净投入；负值 = 盈利，不触发
- 实测：净投入 = (800+989.01+500) - 1917.92 = 371.09；回撤 = (371.09-500)/371.09 = **-34.7% → 盈利，正确不触发** ✓

`check_discipline()` 第 3 层回撤计算改为净投入口径（见上），并保留可回退（v1 逻辑注释保留）。加单测覆盖「盈利组合不误报」。

### B. decision_desk.py 加 discipline 段

```python
from discipline_checker import check_discipline  # 复用，不复制逻辑

PORTFOLIO_PATH = ROOT / "data" / "portfolio.json"
RULES_PATH = ROOT / "config" / "discipline_rules.json"

def _build_discipline() -> dict:
    """纪律检查段；独立 try/except，失败给 {error} 不拖垮其他段。"""
    try:
        portfolio = json.loads(PORTFOLIO_PATH.read_text(encoding="utf-8-sig"))
        rules = json.loads(RULES_PATH.read_text(encoding="utf-8-sig"))
        return check_discipline(portfolio, rules)
    except Exception as e:
        return {"error": str(e)}
```

`build_decision_desk_context()` 返回值加 `"discipline": _build_discipline()`（放在现有三段之后）。
