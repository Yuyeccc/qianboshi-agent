## 三、方案设计（v1，schema 先行）

### A. 原文指针导出（Mac `export_dimensions.py` v5 → 本地 data/views/dimensions_export.json）

dimensions 每条新增 `evidence` 子对象（确定性，零 LLM）：

```json
"evidence": {
  "bv_id": "BV1rwjGztEWt",
  "start_ms": 183080,
  "end_ms": 195160,
  "ts_display": "00:03:03-00:03:15",
  "quote_text": "……原文引用……",
  "segment_text": "……transcript_segment 原文片段……",
  "segment_source": "2026.8.13 （钱博士） BV1rwjGztEWt.md",
  "anchor": "anchored"        // anchored | missing(占位锚点1487条)
}
```

- 取段规则：`transcript_segment WHERE raw_asset_id = bv_id AND start_ms >= anchor_start_ms ORDER BY start_ms LIMIT 1`（最近邻首段），再拼上相邻段至覆盖 end_ms（上限 3 段，防超长）
- 占位锚点：`evidence.anchor = "missing"`，渲染层显示「❔原文缺失」，禁止猜时间戳
- 幂等：每次导出全量重建 JSON，不写库

### B. 冲突中心（Mac 新脚本 `conflict_detector.py`，确定性，只算不改库）

**冲突定义（v1 规则）**：同一 `(topic, subject_entity)` 组合下 bullish 与 bearish 并存 → 冲突组。
- 分边：stance ∈ {bullish, bearish} 才参与；neutral/risk/watch 不参与对立分边（可作组内背景成员）
- 组标识：`cf_<topic>_<entity哈希>`；输出 `conflicts_export.json` 并入导出（或独立文件）
- 每组字段：`{conflict_group_id, topic, subject_entity, bull_members: [view_id...], bear_members: [view_id...], n_bull, n_bear, members_detail: [{view_id, stance, claim, date, evidence}]}`
- **不写库**（红线#7）：conflict_group_id 列暂不回填，冲突信息走导出 JSON 下行渲染。是否回填等 gpt 审完再定
- 边界：subject_entity 为空的行（1643 条）不参与分组（数据缺失不猜测）

### C. 渲染层（本地）

1. **claim_dimensions.py**：
   - 挂载 `evidence` + `conflict_group_id`
   - 新徽标：`🔍原文`（anchored，可点击展开）/ `❔原文缺失`（missing，禁猜）
   - 新徽标：`🔀冲突组N`（该 view 属于某冲突组时）
2. **brief_renderer.py 观点表**：加「原文」列（🔍 链接位）；详情展开 = 原文片段 + 时间戳 + 来源文件 + BV
3. **冲突展示（详情页/卡片）**：同一冲突组的多空双方原文并列对照，**不做方向暗示、不合并结论**（红线#3/#4）
4. **无来源数字门禁**（新脚本 `evidence_gate.py` 或并入 post_check）：扫描首屏重大结论区块 → 提取数字（价格/百分比/市值）→ 校验其所在句子的观点行是否带 evidence 锚点 → 无锚点的数字标记 `⚠️无来源数字` 并给出缺失清单；**阻断上线（errors>0 不发）**

### D. stale 标签疲劳一并解决（gpt 上轮建议）
- 表格行不再逐行刷「过期」：行内只显示 `🔍原文` + 疑点标签压缩（如 `过期` 仅出现于详情）
- 汇总行（topic 级）显示过期比例统计，详情页展开具体哪些过期
