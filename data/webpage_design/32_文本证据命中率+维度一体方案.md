# 32_文本证据命中率+维度增补一体化方案.md — task2 combined

> 生成：老手 | 依据：gpt 维度评审（31_）+ 交接文档待办
> 目标：**文本证据命中率真实化**（指标4从22%技术命中→真实证据支撑），并**综合落维度增补**（证据权威分级 + 推理类型 + 因果主线）。用户指示"这些之后的事情综合进去，在修改时顺便做"。

---

## 0. 一句话

用 gpt-5.6-sol 对已锚定观点：**从时间窗候选原文里选最支撑该观点的 quote → 定位 segment+时间 → 标证据权威/推理类型/因果主线**，把"技术命中"升级为"证据支撑"，一次性落进维度字段。

## 1. qianboshi 场景的证据权威等级（直播证据≠官方文件，不能照搬 OpenJury Tier）

| 等级 | 含义 | 场景 |
|---|---|---|
| **A 直接原话** | quote 逐字来自分析师直播 transcript（原文引用） | "钱博士原话：科技牛继续" |
| **B 近距转述** | 保留关键语义的原话概括（paraphrase） | 一句话转述核心逻辑 |
| **C 二手概括** | 他处转述/摘抄，非直接源于本场直播 | 别的账号转述 |
| **D 推断** | 不是我方/分析师原话，是解读或推测 | Agent 融合判断 |

> 原则：A/B 是"分析师说了什么"的可靠证据；C 弱；D 是"我们判断的"，非证据本体。重大结论仅 A/B 可支撑（对齐 gpt：source_tier 决定能否撑重大结论）。

## 2. 推理类型 inference_type（区分分析师陈述本质）

```
fact(事实陈述) / interpretation(解释判断) / correlation(相关性)
hypothesis(假设) / causal_claim(因果断言) / forecast(预测)
```
> 防"推测"被当"事实"。落地到 claim 层。

## 3. 因果主线 topic（观点归主线）

从观点 entities + claim 推断 1-2 个词的主题主线（如 半导体/存储/算力/光模块/铝/电池）。主线用于 report 收敛（≤3条）。

## 4. 执行流程（evidence_tagger.py）

```
对每条已锚定观点（anchor_start_ms 非空 + BV 有 transcript）：
  1. 确定性预筛：取 time window ±10s 的候选 transcript 段（含文本+时间戳）
     → 若窗口内候选段过多，按关键词(实体名)预筛到 ≤8 段
  2. 调 gpt-5.6-sol（stream）：输入 观点(claim/evidence/entities) + 候选段
     → 输出 JSON: {quote, segment_start_ms, segment_end_ms,
        evidence_authority(A/B/C/D), inference_type, topic,
        match_quality(0-1), supported(true/false), reason}
  3. 落库：view_evidence_annotation（新表）
  4. supported=true → 精化 view_evidence_link（精确 quote 定位）
```

## 5. 表结构（新增 `view_evidence_annotation`）

```sql
CREATE TABLE view_evidence_annotation (
  view_id TEXT PRIMARY KEY,
  quote_text TEXT,
  segment_id TEXT,
  anchor_start_ms INTEGER, anchor_end_ms INTEGER,
  evidence_authority TEXT,     -- A/B/C/D
  inference_type TEXT,         -- fact/interpretation/...
  topic TEXT,                  -- 因果主线
  match_quality REAL,          -- 0-1
  supported INTEGER,           -- 1=证据支撑
  reason TEXT,
  model TEXT, created_at TEXT DEFAULT (datetime('now'))
);
```

## 6. 成本与范围控制
- **只对已锚定观点**做（约 6817 条），且先 5 条试点验证 prompt 质量，再扩
- gpt-5.6-sol 单条 stream 调用；试点后可调 `--limit` 控制批量
- 不重复标注（view_id 主键，重跑覆盖）

## 7. 成功标准
1. 试点 5 条：gpt 能正确选 quote + 定位时间 + 标 authority/inference_type/topic
2. match_quality 高、supported 判定合理（真支撑 vs 无支撑分清）
3. 指标4 从"22% 技术命中"变为"证据支撑率"，并给 evidence_authority 分布
