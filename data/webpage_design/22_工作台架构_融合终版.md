## 0. 审核结论摘要

| 维度 | 老手版 | gpt 版 | 终版采纳 |
|---|---|---|---|
| 保真模型 | 证据片段库（1 层） | 五对象模型（4 层） | **gpt 的五对象，落地用老手的增量式** |
| 前提校验（新事件↔观点） | ❌ 无 | ✅ supported/challenged/unrelated/pending | **gpt 的（N1 的灵魂）** |
| Agent 组织 | 单 Agent + 六因子 | 三 Agent + Orchestrator | **gpt 的三 Agent 分工 + 老手的六因子模板** |
| 多用户 | 公共/私有双层 | User→Workspace→Private+Shared | **融合（gpt 模型 + 老手分层）** |
| 技术栈 | SQLite+ChromaDB 轻量 | Postgres+pgvector+MinIO+Redis+Celery | **老手的轻量起步 + gpt 的迁移口子** |
| 分期 | Phase1-3 | Phase0-3 | **gpt 的 Phase 0 思路（先止损）+ 老手节奏** |
| 前端 | 卡片+对话+轨迹 | 今日工作台+证据抽屉+轨迹 | **融合，默认入口用 gpt 的"今日工作台"** |

**核心共识（两份独立都指向同一结论，可信度高）**：
1. 保真 = 原文永存 + 分层引用 + 可下钻（不能只存摘要）
2. 事实/观点/推理三层分离存储
3. 租户隔离从第一天进数据模型
4. 不让 LLM 直接写事实库
5. 渐进迁移，不推翻现有管道

## 1. 数据保真层（最高优先级）

### 五对象模型（gpt 版，采纳）

```
raw_asset（视频/音频/新闻原文）            ← 不可改写，永久保存
   └─ transcript_segment（ASR 片段）       ← 起止时间/置信度/说话人，可校正出新版本
        └─ reasoning_unit（推理单元）      ← 一个完整论证：结论+依据+条件+反例+原文引用
             └─ claim（观点）              ← 原子观点：立场/置信度/有效窗口/证伪条件
                  └─ research_output（回答/日报/卡片）← 派生数据，可再生成
```

**关键字段（reasoning_unit）**：
```json
{
  "thesis": "碳酸锂价格反弹不代表供需反转",
  "premises": ["库存仍在累积", "新增产能尚未出清"],
  "conditions": ["需求端没有超预期政策刺激"],
  "counter_arguments": ["若下游补库持续超两周需修正"],
  "asset_refs": ["碳酸锂", "电池ETF"],
  "source_segment_ids": ["seg_101"],
  "source_time_range": ["01:12:08", "01:15:47"]
}
```

### 落地方式（老手版增量式，采纳——不重构现有管道）

```
现有：直播 → ASR → transcribe_to_note(结构化) → view_extractor(观点)
改造：直播 → ASR → ① evidence_extractor(新脚本, 切语义段+打标+存reasoning_unit, flash即可)
                   → ② 现有结构化照跑，笔记/观点加 evidence_ids 列
```

- 新增独立脚本 + 2 个新表 + 现有表加列（迁移脚本有先例）
- evidence_extractor 失败**不阻塞**主链路（降级：无片段也能跑）
- 检索策略（gpt 采纳）：命中 claim → reasoning_unit → 相邻 ASR 片段（前后 1-2 段防断章取义）→ 新闻/公告事实 → LLM 组织回答附证据编号

## 2. 多源消息 + 前提校验（N1 的灵魂，gpt 版核心贡献）

### 统一事件模型
所有外部源 → `source_event`（source_type/raw_content_uri/content_hash/published_at/entities/event_type/reliability），content_hash 去重，published_at≠fetched_at 防旧闻误判新。

### 首批源（务实，不爬不稳定站点）
| 类别 | 来源 | 频率 |
|---|---|---|
| 分析师 | B站直播（现有） | 日更 |
| A股/ETF 行情 | 合规 API（腾讯 ifzq 现有） | 分钟级 |
| 期货/商品 | 碳酸锂/有色/原油 | 分钟级 |
| 新闻 | 财经 RSS/API | 5-15 分钟 |
| 公告 | 巨潮/交易所 | 小时级 |
| 宏观 | 统计局/央行日历 | 日/月 |

### ★ 前提校验（gpt 独有强项，必采纳）
新事件对分析师观点输出**四种状态**而非"对/错"：

| 状态 | 含义 | 示例 |
|---|---|---|
| supported | 新事实支持观点关键前提 | 锂盐厂减产↑ 支持"供给过剩缓解"？→ 反向 |
| challenged | 新事实冲击关键前提 | 某厂宣布减产 → 供给收缩，与"过剩"前提相悖 |
| unrelated | 相关性弱 | 一家家电公司公告 |
| pending | 数据不足 | 减产规模未明 |

输出带"原因 + 待观察指标"。**这比新闻情绪摘要有用得多**——直接对应你说的"分析师的逻辑很容易被消磨"：前提不丢，新事件来了能校验前提。

## 3. Agent 层（gpt 三 Agent + 老手六因子）

### 三 Agent + Orchestrator（gpt 采纳）
```
Research Orchestrator（意图分类：查观点/查事实/独立研究/持仓风险/决策复盘）
├─ Analyst RAG Agent：还原"分析师怎么想"（推理链+观点时间线）
├─ Independent Analysis Agent：未覆盖资产的独立判断（行情+新闻+公告+宏观）
└─ Portfolio Risk Agent：用户持仓暴露与风险（持仓+成本+关联观点）
```

### 独立分析模板（老手六因子 + gpt 三层输出）
```
分析模板（可审计，模型填充不自由发挥）：
1. 资产定义（标的/行业位置/核心驱动）
2. 当前状态（价格/估值/基本面/政策/资金）
3. 多空论点（每边带可验证依据）
4. 关键变量（什么数据变化会改判断）
5. 情景推演（基准/乐观/悲观）
6. 证伪条件（什么发生则结论失效）
7. 行动边界（观察/等待/风险提示，不下单）

输出三层：事实层（行情/公告/新闻）→ 推理层（如何推导）→ 结论层（判断+置信度+风险）
无证据部分必须标注"分析假设"，禁止伪造事实。
```

### LLM 分工（已有策略延续）
flash：分类/抽取/去重/初步结构化/普通问答；sol：跨源冲突/复杂研究/复盘。**sol 的 3500 token 预算只投高价值决策**；每轮最大工具数/引用数可配置防失控。

## 4. 多用户隔离（融合版）

```
User → Workspace（个人工作区）→ Private Data（持仓/决策/会话/笔记）
                          └──→ Shared Research（公共研究库：观点/证据/消息/RAG）

私有表必备：workspace_id + created_by + visibility(private|workspace|shared)
API 层：JWT → current_workspace → repository 显式过滤，禁止前端传任意 user_id 查询
角色：admin / beta_user / viewer；admin 不能看用户私有持仓
审计日志：登录/导出/查看私有决策/Agent 调用/管理员操作
限流：对话和导出按用户配额（内测防拖垮 sol 预算）
```

## 5. 技术栈（老手轻量起步 + gpt 迁移口子）

```
起步（单人可维护）：
  frontend/  React+TS+Vite+TanStack Query+Zustand（作品集站同栈）
  backend/   FastAPI+SQLAlchemy+Pydantic（作品集 backend 已有经验）
  worker/    APScheduler（现有 cron 风格）→ 任务多了再 Celery
  database/  SQLite 起步（现有）→ 多用户后迁 PostgreSQL（Alembic 迁移）
  vector/    ChromaDB 继续用（现有）→ 将来 pgvector 双写切读
  object/    音频已本地存储（现有 E:\qianboshi-agent\audio），暂不引入 MinIO
  cache/     Redis 只在需要限流/队列时引入（Phase 2+）
```

**决策依据**：单人开发 + 内测 ≤ 30 人，Postgres/MinIO/Redis/Celery 全部是过度设计。**留迁移口子但不提前上**——接口层用 Repository 模式，换库只改实现。

## 6. 前端交互（融合）

```
布局：左（工作区/资产/观点/持仓/决策） 中（今日工作台） 右（证据抽屉）
默认入口：今日工作台（盘前重点/持仓变化/昨夜新观点/待验证前提/风险事件）← gpt
卡片流：结论卡/多空卡/证据卡/风险卡/行动卡 ← 双方共识
对话回答 = 可渲染块（文本+内嵌卡片），卡片可下钻 reasoning_unit → ASR 原文 → 视频时间点
工具轨迹：简洁执行轨迹（查了哪些源/命中几段/基于几条证据/几个待验证假设）
         ← 展示可验证的数据操作轨迹，不暴露 CoT（gpt 这一点更成熟）
```

## 7. 分期路线（gpt Phase 0 思路 + 务实节奏）

### Phase 0：数据底座止损（1-2 周）★ 先解决你最大的痛点
- ASR 保留完整 JSON（当前可能只存了文本？核查）
- evidence_extractor：切语义段 + reasoning_unit 入库
- 现有笔记/观点加 evidence_ids，迁移历史数据（回填）
- 验收：**任一日报观点可下钻到直播原文时间点**

### Phase 1：单人 MVP（2-3 周）
- FastAPI + React 骨架 + 登录（先单人）
- 只读研究 API：资产卡/多空卡/证据链（复用现有 builder）
- 研究对话（SSE 流式）+ 卡片渲染 + 工具轨迹
- 接入行情/新闻/公告三类源 + 前提校验 v1

### Phase 2：内测（+2-3 周）
- 多用户：邀请码/配额/持仓隔离/审计
- 三 Agent 完整化 + 独立分析模板
- 订阅提醒：持仓关联事件/观点被挑战/证伪条件触发
- 决策记录 + 复盘

### Phase 3：付费准备（后续）
- 工作区套餐/模型额度/数据源权限
- 报告导出（MD/PDF）/分析师历史战绩
- OpenAPI / MCP Server（开放接口，不绑 DSH）

## 8. 实施边界（双方共识 + gpt 补充）

1. LLM 不能直接写事实库（只能写观点/推理/报告，带证据引用）
2. 原始 ASR 与上下文不删除（校正生成新版本）
3. 分析师观点与 Agent 判断**分字段存**（责任主体/证据标准/可信度不同）
4. 不做自动交易/买卖指令（定位：研究/风险提示/决策复盘）
5. 先做可追溯研究闭环：事件→推理链→观点→决策→复盘，闭环后再扩源扩能力
6. **不要一开始上 Kafka/微服务/复杂 Agent 平台**（gpt 原话："先单体"）
