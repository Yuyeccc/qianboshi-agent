## 1. 系统定位与红线

### 1.1 系统定位

本项目不是普通 RAG 问答，也不是买卖信号软件，而是：

**多分析师公开视频观点理解 + 结构化观点库 + 证据链保真 + 行情验证 + 个性化盘前简报 + 决策复盘 + 后续自动化视频生产。**

系统必须能够回答：

- 这个观点来自哪段原文？
- 原文是直接陈述、近距转述、二手概括，还是模型推断？
- 这是事实、解释、相关性、假设、因果主张还是预测？
- 观点依赖哪些前提？当市场结果出现后，原始判断依据是否成立？
- 内容是否越过合规边界，是否存在数据、时间戳或来源问题？

### 1.2 基础原则（v0.3 沉淀 + 认知内核强化）

1. **RAG 降级为证据补充器**：从"主判断器"降级，只补原文证据，不决定"今天最新观点"。
2. **简报主观点结构化来源**：必须来自 `latest_digest` 或 `structured_views/query_views`，不走 embedding。
3. **硬过滤 + 分桶排序**：日期、实体、来源、观点类型先硬过滤，桶内才打分（A>B>C>D>E）。
4. **行情事实层与观点层分离**：非交易时段只显示昨收/缓存价，不伪装实时涨跌。
5. **LLM 只做综合表达**：不做检索裁判、数据验证和最终格式控制。
6. **观点可回溯**：每条观点必须能回溯到 `view_id/source_file/date/analyst/evidence`。
7. **验证闭环**：后续用 view_id 做 1/3/5/10/20 日收益、超额收益、最大回撤验证。

### 1.3 认知内核新增原则（v0.4~v0.5）

- **原始数据不可变**：原始 JSONL 只读 + MD5 校验；清洗/补全/抽取结果不覆盖原始事实。
- **事实库零 LLM 写入**：LLM 只写观点/推理/证据引用/标签/解释性元数据；事实以原始采集、结构化转录和可验证外部数据为准。
- **不猜数据**：MISSING_BV 不按文本相似度猜测；`00:02:82` 不进位；无法可靠绑定的数据保留问题状态，不伪造确定性。
- **证据权威与推理类型分离**：一段引用是否为分析师直接原话（A/B/C/D），与观点属于事实/解释/预测（inference_type），是两个独立维度。
- **置信度分维度表达**：证据置信度、推理置信度、预测置信度分别记录，不压缩成单一总分。
- **认知链可复盘**：决策记录不仅保存结论，还保存当时的 premise；事后复盘必须能重建"当时基于什么信息作出判断"。
- **不确定性显式化**：时间戳异常、证据不足、推理跳跃和生命周期变化通过 view_quality_issue / support_level / materiality / lifecycle_status 显式记录。
- **合规下沉系统层**："不荐股"不必然排除投资咨询属性——意图分类/禁词拦截/留痕不能只靠 System Prompt。

### 1.4 红线（贯穿全项目）

- 原始数据 immutable（jsonl 只读，md5 校验）
- 零 LLM 写事实库；LLM 只写观点/推理/证据引用
- 不猜数据（MISSING_BV 不按文本猜；`00:02:82` 不进位）
- 不提供买卖建议（compliance gate 兜底）
- 不丢差异化护城河（分析师推理链保真/多源校验/决策复盘/A港美分域）

## 2. 当前架构总览（已建成）

### 2.1 数据流全景

```text
采集层    monitor_bilibili → yt-dlp → Whisper ASR → ASR纠错 → 结构化笔记(Markdown)
知识层    view_extractor → structured_views.jsonl → view_store（分桶排序+质量排除）
质量层    qianboshi_quality.db（观点层：raw/provenance/link/annotation/claim/reasoning_unit）
证据层    qianboshi_evidence.db（transcript_segment 136万）
决策层    qianboshi_decision.db（决策日志/辩论卡/预测/因子/资产卡）
输出层    agent --brief → brief_json → schema校验 → render_markdown → post_check → 视频生产
```

### 2.2 三库分层（全部已建成）

| 库 | 层 | 内容 | 规模（2026-08-30 实测） |
|---|---|---|---|
| `qianboshi_evidence.db` | 证据层 | 结构化转录段（BV/时间戳/文本/分析师） | transcript_segment **1,364,250**（orphan 仅 4） |
| `qianboshi_quality.db` | 观点层 | 观点+证据关联+维度标注+claim | view_raw 11,311 / provenance 11,311 / link 48,593 / annotation 596↑ / claim 501 / reasoning_unit 1,143 |
| `qianboshi_decision.db` | 决策层 | 决策日志+辩论卡+预测+因子+资产卡 | 详见 §6.3 |

职责隔离：证据、观点质量、决策分别落库；上层模块通过明确接口读下层结果，不把用户决策、模型推理或渲染状态回写成原始事实。

### 2.3 质量闸门（Phase0 已落地）

- **immutable 导入**：view_raw 只写一次，md5 留底
- **timestamp 校验**：`00:02:82` 不进位；TS_UNIT_AMBIGUOUS / INVALID_TS_FORMAT / TS_OUT_OF_DURATION / TS_REVERSED 四类问题进 `view_quality_issue`（3,538 条）
- **BV 补齐**：MISSING_BV 1,049 → 0（fix_missing_bv.py，标题精确匹配，零 LLM）
- **幻觉时间戳排除**：605 条 TS_OUT_OF_DURATION 定性为 LLM 幻觉（音频时长翻案数=0），导出 `excluded_view_ids.json`（609 条含 4 条 reversed），view_store 加载时排除（load_views 11,312 → 10,702），30d 检索窗口干净。**排除发生在检索入口，不是删除数据**——原始记录与质量问题仍在库中。

## 4. 认知内核（33号蓝图，三支线）

> 目标：让 qianboshi 从"观点仓库"进化成**有原始证据、可判断可信度、能归主线、会复盘**的财经认知内核。

### 4.1 证据链保真（✅ 已建成）

- 观点→原文下钻：view_evidence_link **48,593** 条关联
- anchored 可下钻 **7,773 / 11,311**（68.7%）
- 证据链至少保留：观点、来源转录段、视频 BV、时间窗口、链接关系；检索层排除异常观点 ≠ 删除原始记录

### 4.2 维度增补（task2，🔄 跑批中）

- **证据权威四档**（直播场景）：A直接原话 / B近距转述 / C二手概括 / D推断；重大结论仅 A/B 可支撑
- **推理类型**：fact / interpretation / correlation / hypothesis / causal_claim / forecast（防"推测"被当"事实"）
- **因果主线 topic**：观点 entities+claim 归 1-2 词主线（半导体/大盘/光模块/算力/黄金…），report 收敛 ≤3 条
- **执行**：evidence_tagger.py，只对已锚定观点（先 500 试点后扩 1400）
- **试点成果（500 条，2026-08-29）**：
  - 权威分布：A 259(52%) / D 154(31%) / B 48(10%) / C 40(8%)
  - 推理类型：interpretation 205 / causal_claim 119 / fact 114 / forecast 51 / correlation 10 / hypothesis 2
  - **真实证据支撑率 54.7%**（supported 274/501）——技术命中(22%)≠内容支撑(54.7%)，分得清"落进时间窗"和"原文真撑观点"；D(推断)类非原话多因候选段无直接对应原文，标 unsupported 进"待重标/人工"
- **当前跑批**：1400 全量进行中（596/1400，2026-08-30 21:00；当前分布 A306/D185/B61/C42，supported 320/274）

### 4.3 认知闭环（✅ 结构已建）

```text
evidence → view → annotation → claim → decision premise → prediction/outcome → decision review
```

- **claim 层**：claim 501 条，含 三维 confidence（evidence_confidence/reasoning_confidence/forecast_confidence）+ support_level + materiality + lifecycle_status（全 501/501 填充）
- **决策复盘**：decision_db 条件树（premise 前提 + invalidation 失效条件），复盘先查前提是否仍成立；user_decision_logs.premise 保存决策当时条件，避免事后用新信息重写旧判断
