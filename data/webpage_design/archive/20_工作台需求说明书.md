# 钱博士投研工作台 — 需求说明书（用户确认版 2026-08-29）

## 一、产品定位

把 qianboshi-agent（B站财经直播采集→ASR→结构化→RAG→日报→决策复盘 的 Python 管道）
升级为一个**多用户、混合交互（卡片+对话）、带实时消息输入和独立分析逻辑**的投研 Agent 工作台。

未来商业化方向：付费 agent（信息/工具/服务型）。现在：单人 + 内测开放部分人。

## 二、用户确认的关键决策

1. **多用户**：目前单人使用，但内测要开放给部分人，允许其**输入自己的持仓** → 必须做多用户隔离（登录、持仓隔离、决策隔离）
2. **混合交互**：既要**卡片式**（资产卡/多空卡/证据链展示），也要**对话式**（讨论想法、讨论工作台里没有提到的股票）
3. **历史战绩**（分析师历史准确率）：可以慢慢做，不是第一优先级
4. **核心痛点（最高优先级）**：
   - Agent 需要**更多的消息输入源**，不单单依赖分析师直播
   - **分析师的逻辑很容易被消磨**：直播里提到的丰富推理过程，经"总结"后丢失大量信息（ASR→结构化→观点抽取 逐层压缩失真）

## 三、使用场景清单（用户确认过）

### A. 研究类（只读，最高频）
- A1 盘前速览：开盘前"今天盯什么"→ 昨晚直播新观点 + 持仓相关变化 + 多空信号
- A2 板块/资产深研：资产分析卡 + 多空对照 + 证据链 + （远期：分析师历史战绩）
- A3 多分析师对照："钱博士和旗帜鲜明对锂矿怎么看？分歧在哪"
- A4 证据下钻："为什么说碳酸锂供给过剩？" 一路钻到 ASR 原文片段
- A5 观点时间线：某资产观点随时间的演变（可选）
- A6 新内容增量："昨晚直播有哪些新观点/新变化"

### B. 决策类（写操作，低频高价值）
- B1 决策记录：记下判断/理由/信心度/证伪条件
- B2 决策复盘：自动对照结果，出认知修正
- B3 持仓联动：问"我的电池ETF现在什么状态"→ 持仓+观点+风险

### C. 过程/信任类
- C1 过程审计：某次分析用了哪些工具、查了哪些观点、实时数据还是缓存
- C2 来源标注：每条结论带"谁说的、哪天说的、原文出处"
- C3 研究导出：打包 Markdown/PDF（可选）

### D. 未来付费向（架构留口子）
- D1 多用户隔离（现在就要做）
- D2 限流/配额
- D3 开放 API/MCP

## 四、新增需求（本次对话用户明确提出）

### N1. 多源消息输入（不只靠分析师）
Agent 应能实时关注：行情、新闻、公告、期货、宏观数据等，与分析师观点交叉验证。

### N2. 独立分析逻辑（Agent 自己会分析）
Agent 需要拥有"类似分析师的一套分析逻辑"，能对工作台里没有提到的股票/板块
给出自己的分析（基于多源消息 + RAG 观点 + 分析框架），而不只是转述分析师。

### N3. 信息保真（核心痛点）
现有管道 直播→ASR→结构化笔记→观点抽取 逐层压缩，分析师的推理链/语境丢失。
架构必须解决：**保真度优先**——保留原始推理链、条件假设、上下文，压缩不能丢逻辑。

## 五、技术约束

- 现有资产：E:\qianboshi-agent（Python 管道：采集/GPU转写/结构化/RAG(ChromaDB)/日报/决策库 SQLite）
- 现有前端技能：React + TypeScript + Vite（作品集站）
- 后端：Python FastAPI（作品集 backend 已有 FastAPI 经验）
- LLM：deepseek-v4-flash（routine）/ gpt-5.6-sol premium（analysis，3500 token 上限）
- 用户是单人开发者，架构必须**轻量可维护**，不能引入无法维护的重框架
