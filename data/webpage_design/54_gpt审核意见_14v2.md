1. `any_ok` 聚合：结论为可用，但必须明确其语义是“view 内存在至少一个可用 reasoning unit”，不是“整条推理链完整”。建议在方案 A 增加优先级规则：`ok > partial_anchor > template_only`，多状态 view 只保留最高层级，并同时输出 `status_count`；`no_ru` 单独处理。禁止把 `any_ok` 结果表述为完整五元组验证，保留 `strict` 口径用于敏感性对照。

2. OOS 切分：单一 `2026-06-30/2026-07-01` 切分可以作为首版验收，但不足以证明稳定性，尤其 test 期较短且分层后样本进一步减少。建议保留该时间点作为主切分，同时增加至少 2 个滚动窗口或 expanding walk-forward；每段均报告样本量、命中率、Wilson CI，并要求 test 期不得为空。

3. `template_only` 解读：不能用“显著高于 50%”直接证明模板具有预测能力。模板可能包含方向性词、风险阈值或隐含先验。建议将该层定位为“弱语义/污染对照层”，只做基准和污染检测；只有在预注册规则、独立 OOS、多窗口复现且效果显著时，才允许称为预测证据。报告中增加效应量及与 `ok` 层的差值 CI。

4. `error` 覆盖率：12666/31320 约 40.4%，仅报告 coverage 不够。`error` 是行情缺失导致的不可解析，不应进入命中率分母，但必须按窗口、实体、来源、日期报告。建议增加 `resolved / error / skipped / eligible` 四类分母，并将“可评估覆盖率”定义为 `resolved / (resolved + error)`；暂不把 8 月 backfill 混入本次回测，另做数据修复后的复跑对照。

5. `no_ru` 层：应纳入主报告，但标记为“无推理链参考层”，不得与三种有 `tuple_status` 的层竞争预测结论。单独报告其数量、覆盖率和命中率，作为缺失机制诊断；若该层包含未锚定或低质量文本，应避免任何“模型能力”解释。

6. 报告字段：当前字段基本齐全，但还缺少 `eligible_n`、各状态原始计数、去重前后事件数、分层规则版本/hash、代码版本、数据快照/hash、缺失原因、统计检验方法及多重比较说明。JSON 与 Markdown 必须共享同一结构，并记录生成时间、命令行参数和 OOS 窗口。

7. 统计方法：Wilson CI 合适；应按 `bullish / bearish / risk` 分向报告，避免牛熊不对称被总命中率掩盖。`partial_anchor` 仅 575 个 view，建议设置 `min_sample`（如 30）并显示“样本不足”，不要据此下强结论。50% 二项检验需明确双侧/单侧、显著性水平，并同时报告实际命中率、CI 和效应量。

8. 其他问题：方案中的“随机基准显著则模板可用”逻辑过强，显著偏离 50% 也可能是标签、样本选择或市场非平稳造成；应增加方向基准、窗口基准及置换检验。`prediction_backtest_layers` 建议加唯一键 `(run_id, layer, window, horizon, direction)`，避免重复写入；回滚应使用事务和明确的 run_id，而不是直接 `DROP`。

**方案修订清单**

1. 明确 `any_ok` 与 `strict` 定义、优先级及多状态 view 处理。  
2. 保留 2026-07-01 主切分，新增至少两段 walk-forward。  
3. 将 `template_only` 改为对照/污染层，限制结论措辞。  
4. 增加 `eligible_n` 与 error/skipped 分母及分原因 coverage。  
5. 将 `no_ru` 纳入主报告但禁止纳入能力结论。  
6. 补齐报告元数据、版本/hash、去重计数和统计检验字段。  
7. 增加方向分层、最小样本阈值、效应量和多重比较说明。  
8. 为结果表增加 `run_id` 唯一约束，采用事务写入和可恢复回滚。
