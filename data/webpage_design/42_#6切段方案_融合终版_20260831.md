## 三、方案设计（融合定稿，gpt 设计为主）

### A. Schema 迁移（Mac 新脚本 `ru_schema_migrate.py`，幂等，一次性）

```sql
ALTER TABLE reasoning_unit ADD COLUMN premise TEXT;            -- 成立前提/观测事实；无→NULL
ALTER TABLE reasoning_unit ADD COLUMN mechanism TEXT;          -- 前提到结论的因果/传导路径；非因果→NULL
ALTER TABLE reasoning_unit ADD COLUMN conclusion TEXT;         -- 核心判断/预测；core_claim 必填
ALTER TABLE reasoning_unit ADD COLUMN trigger_condition TEXT;  -- 使结论成立/触发行动的条件；无→NULL
ALTER TABLE reasoning_unit ADD COLUMN invalid_condition TEXT;  -- 使结论失效/反转的条件；无→NULL
ALTER TABLE reasoning_unit ADD COLUMN tuple_confidence REAL;
ALTER TABLE reasoning_unit ADD COLUMN tuple_status TEXT DEFAULT 'ok';  -- ok|template_only|needs_review
ALTER TABLE reasoning_unit ADD COLUMN schema_version TEXT DEFAULT 'ru_v1';
-- 旧 1143 条标记 legacy 保留
UPDATE reasoning_unit SET schema_version='ru_v0_legacy' WHERE schema_version IS NULL;

CREATE INDEX IF NOT EXISTS idx_ru_asset_time ON reasoning_unit(asset_id,start_ms,end_ms);
```

红线#6：**跑批期间禁 DDL**——迁移先做，跑批只写行。

### B. 模板句识别（复用 #13 词典正则 `is_template_claim`，规则版本化 ru_tpl_v1）
- 命中模板 → 确定性生成 conclusion unit：conclusion=claim_text，其余四列 NULL，tuple_status='template_only'，**不调 LLM**
- 误切风险兜底：实质句若被模板正则误命中 → 抽样审核队列（见 E）

### C. 窗口构建（`ru_window_build.py`）
- 按 asset_id + start_ms 时间邻近合并窗口（参考旧 reasoning_unit_window 236 窗）
- **窗口内必须包含全部 claim_id**（修旧版只覆盖 420 的根因）
- 窗口优先级：含 materiality=high 或实质句的窗口先跑
- 幂等：input_hash + schema_version 双键去重；断点续跑（status: pending/done/failed）
- **无锚点 claim 处理（老手自审补）**：占位锚点（anchor_start_ms<=0，1487 条）无原文 span——
  模板句 → 确定性 conclusion；实质句 → **降级确定性 conclusion + tuple_status='partial_anchor'**（不调 LLM，
  原文缺失无法验证 span，红线#2 不猜；完整五元组等占位锚点修复后再补）

### D. anchor_llm 切段跑批（`ru_tagger.py`，gpt-5.6-sol）
- 仅实质句窗口调 LLM：输入（候选句 span + 锚点 quote + claim 摘要，1-2k token）→ 输出五元组 + relation（300-700 token）
- 窗口输出：1 conclusion unit + 独立前提/机制/限定/反驳拆 2-5 unit；unit 对应连续原文 span 禁止跨无关句
- relation_type 统一：supports / contradicts / qualifies / elaborates / depends_on（限定=qualification+qualifies，反驳=counterpoint+contradicts）
- 4 并发，250-350 窗，首轮 30-90 分钟，含重试 2-3 小时预算；失败窗重试 2 次后标 failed+needs_review

### E. 验证口径（`ru_verify.py`，分层抽样 300 条）
- 模板 100 / 实质 150 / high-materiality 50
- 检查：span 与 quote_text 一致性、五元组自洽、模板句不误切、relation 一致
- **门槛**：引用边界 ≥95% / 五元组语义一致 ≥90% / 模板误切 <2%；失败样本 needs_review

### F. 渲染（本地 claim_dimensions.py + brief_renderer.py）
- 详情页新增「论证链」：按 span 顺序渲染 前提→机制→结论，旁挂触发/失效条件 + 限定/反驳折叠
- 五元组数据走导出 JSON 下行（Mac export_dimensions v6 加 reasoning 段）
