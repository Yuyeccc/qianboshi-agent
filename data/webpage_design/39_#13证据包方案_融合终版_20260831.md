## 三、方案设计（v1 融合定稿）

### A. 原文指针导出（Mac `export_dimensions.py` v5，确定性零LLM）

dimensions 每条新增 `evidence` 子对象（**字段级按 gpt 审补全**）：

```json
"evidence": {
  "bv_id": "BV1rwjGztEWt",
  "raw_asset_id": "BV1rwjGztEWt",        // 与 transcript_segment.raw_asset_id 一致
  "segment_id": "BV1rwjGztEWt:183080",   // annotation.segment_id 原文指针
  "anchor_start_ms": 183080,
  "anchor_end_ms": 195160,
  "ts_display": "00:03:03-00:03:15",
  "quote_text": "……tagge 选中的原文引用……",
  "segment_text": "……transcript_segment 原文片段(最多3段拼接)……",
  "segments": [{"segment_id": "…", "start_ms": 183080, "end_ms": 195160, "text": "…"}],
  "segment_source": "2026.8.13 （钱博士） BV1rwjGztEWt.md",
  "source_layer": "primary",             // 冗余冗余：与顶层并列，防渲染丢失
  "verification_status": "verified",
  "confidence": {"band": "high", "min_dimension": "reasoning", "min_value": 0.78},
  "topic": "港股", "subject_entity": "港股",
  "claim_id": "cl_xxx", "view_id": "001d…",
  "content_hash": "sha256:…",            // quote_text 的哈希，可审计
  "extraction_status": "ok"              // ok | segment_missing(占位锚点) | hash_mismatch
}
```

**取段规则（gpt 修正 + 老手自审再修）**：
1. 优先找**包含段**：`raw_asset_id=bv AND start_ms <= anchor_start_ms < end_ms` → 首段
2. 找不到包含段 → 取 `start_ms >= anchor_start_ms` 的首段（旧规则兜底）
3. 顺序拼接后续段至覆盖 `anchor_end_ms`，**上限 30 段 / 总字符 400**（老手自审：segment 平均仅 7.3 字符、最长 26，原"3 段"根本覆盖不了 quote，已放宽），每段保留 segment_id
4. 占位锚点（anchor_start_ms<=0，实测 995 真(0,0) + 492 半占位 = 1487）→ `extraction_status="segment_missing"`，不猜时间戳
5. 一致性校验：quote_text 中出现的数字若不在拼接段文本中 → `hash_mismatch`（标记不阻断；quote 是语义锚，segment 是上下文）
6. 性能：transcript_segment 已有 `idx_seg_bv` 索引（实测确认），710 BV 走索引查询无压力

**幂等**：每次全量重建 JSON；加 `exported_at` + `rule_version=v1_20260831`（gpt：可重复运行标识，后续审计变更）。

### B. 冲突中心（Mac 新脚本 `conflict_detector.py`，确定性，只算不改库）

**冲突定义（v1 定稿 + 老手自审修正分组键）**：同一 `(topic, 实体交集)` 组合下 bullish 与 bearish 并存 → 冲突组。
- **分组键修正（老手自审发现）**：subject_entity 实测 4439/7484 条为**逗号分隔多实体列表**（如 `688981.SS,半导体,先进制程,国产替代,设备材料`），直接按整串分组会把同一实体的不同组合切成孤立组。**修正：subject_entity split(',') 得实体集合，两两求交集；有交集且 stance 对立 → 成组**，分组键 = topic + 交集实体（规范化）
- **分边**：bullish / bearish 对立分边；**risk/watch 不强行归边**（单列风险/观察侧背景，gpt 意见）；neutral 作背景成员
- **组分级（materiality 分层，gpt 意见）**：
  - `primary`：组内任一成员 materiality ∈ {high, medium} → 主冲突（首屏可展示）
  - `background`：仅 low 成员 → 背景冲突（默认折叠，用户展开可见）
- **时间窗**：不做过滤——跨日期相反观点正是"分歧/新变化"信号；组内成员带 date，渲染时展示日期让用户判断时效（v1 务实取舍，规范化+时间窗过滤留 v2）
- 组标识 `cf_<topic>_<entity_hash>`；输出 `conflicts` 数组并入导出 JSON
- 每组：`{conflict_group_id, topic, subject_entity, level, n_bull, n_bear, bull_members:[{view_id, claim, date, evidence}], bear_members:[…], background:[{view_id, stance, claim, date}]}`
- subject_entity 为空（1643 条）不参与分组（数据缺失不猜）
- **不写库**（红线#7：派生数据走导出；conflict_group_id 列不回填，gpt 确认违反"只加列不改历史行"）

### C. 渲染层（本地）

1. **claim_dimensions.py**：挂载 evidence + conflict；新徽标：
   - `🔍原文`（anchored）/ `❔原文缺失`（segment_missing，禁猜）
   - `🔀冲突组N`（primary 高亮，background 灰显）
2. **brief_renderer.py 观点表**：加「原文」列（🔍）；**首屏重大结论 = materiality=high 的行**（gpt 定义），无锚点的 high/medium 不得进首屏（门禁保证）
3. **两次点击落地（gpt 务实方案）**：
   - 第一击：观点行「🔍原文」→ 同日报**详情锚点**（详情区：segment_text + ts_display + segment_source + 来源分析师/日期）
   - 第二击：详情区 BV 深链 `https://www.bilibili.com/video/BVxxx?t=183s`（真实可点 HTTPS）+ 原始文件路径文本
4. **冲突展示**：详情区/卡片将同组 bull/bear 成员原文**并列对照**，不做方向暗示、不合并结论（红线#3/#4）；neutral/risk/watch 背景成员单列
5. **stale 标签疲劳**（一并解决，gpt 上轮建议）：表格行不再逐行刷「过期」；行内只显示 🔍原文 + 疑点压缩；topic 汇总行显示过期比例，详情展开具体过期项

### D. 无来源数字门禁（本地新脚本 `evidence_gate.py`，post_check 调度）

- **独立脚本**（gpt 意见：便于单测+阻断发布），由 post_check 调用
- **数字识别**：货币/价格/百分比/涨跌幅/bps/倍数 + 中文金额单位（亿/万/百万）；排除日期/时间戳/条数/编号
- **数字来源追溯链（老手自审补闭环）**：渲染句数字 → 对应 view 的 claim_text → quote_text/segment_text **包含校验**（quote 不含该数字 = 无来源）
- **无来源判定**（任一命中即阻断，列清单）：
  1. 首屏重大句（materiality=high）含数字，但关联 claim 无 evidence
  2. evidence.anchor=missing（segment_missing）
  3. 数字在 quote_text 中不存在（追溯链断裂）
- 输出 `⚠️无来源数字` 清单；errors>0 阻断上线（不发飞书）
